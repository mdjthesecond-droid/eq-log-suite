Alert Rules

Rules are evaluated by the tailer against every live event.

field_condition syntax help

A small whitelisted mini-language (deliberately not real code, since rules come from this form): field OP value (AND field OP value)*. AND only -- no OR, no parentheses. Operators: = != > < >= <=. Text fields compare case-insensitively; amount compares numerically and is the only field >/< make sense on. Quote a value if it contains spaces, e.g. verb="Lucky Gambit".

fieldmeaning
event_typee.g. melee, ability_damage, spell_damage, spell_heal, threat, combat_state, death, zone_change, gather, rare_found, hail, loot, quest, exp -- varies by game, check /events for what's actually showing up
source_name / target_nameactor name as logged -- literally You for yourself, generic article-prefixed text like a lowland viper for trash mobs, or a proper name for named/unique actors and other players
source_type / target_typeyou, npc (generic trash mob), or unknown (a named actor -- could be a unique NPC, a player, or a pet; not distinguishable from log text alone)
verbmeaning depends on event_type -- it's the ability/spell name for ability_damage/spell_damage/threat, the miss/avoid word (misses, dodges, ...) for an avoided melee swing, or start/stop for combat_state. Notably not where an ability's name ends up for a hit you land yourself -- see example 2.
amountnumeric -- damage or threat amount
outcomehit, miss, riposte, parry, dodge, block, or empty where it doesn't apply

Examples:

  • target_type=you AND amount>200 -- you took a hit over 200 damage, from anything.
  • verb="Lucky Gambit" AND source_type=you AND amount>1 -- your own "Lucky Gambit" ability landed for more than 1 damage. Learned the hard way: source_name="Lucky Gambit" looks right but never matches -- for an ability you land, source_name is literally You, and the ability's name is in verb instead.
  • event_type=zone_change AND source_type=you -- fires every time you zone.
